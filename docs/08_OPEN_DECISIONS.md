# DisasterRescue — Open Decisions / Specification Audit

These are NOT silent corrections to the SRS. They are items the agent must not resolve by guessing.

## DEC-001 — Single role field vs multiple roles

SRS FR-01.5 describes `user.roles[]` and multi-role users.

The Firestore `users` schema shown later contains `role: UserRole`.

Decision required:
- Keep one role
OR
- adopt `roles[]` + active role/context.

Until approved, agents must not change the schema.

## DEC-002 — SMS fallback architecture

Acceptance AC01-03 requires:
2G → SMS → central number → backend parses SMS → creates SosRequest.

The SRS also constrains backend to Firebase/no self-hosted server.

The exact SMS gateway/inbound mechanism is not fully specified.

Decision required:
- external SMS gateway/webhook
- operational/manual relay
- deferred MVP
- another approved mechanism.

Do not pretend Firebase alone receives arbitrary inbound SMS.

## DEC-003 — Field-level privacy strategy

SRS requires unassigned rescue teams to see limited SOS information and assigned teams to see full household information.

The SRS gives a Security Rules concept but does not fully specify the physical data separation needed to prevent unauthorized clients from reading sensitive fields.

Decision required:
- separate public/operational/private documents
- another approved design.

## DEC-004 — Anonymous SOS

AC01-06 permits either quick login or anonymous SOS.

Decision required:
- authenticated-only
- anonymous SOS
- anonymous with later claim/linking.

## DEC-005 — Public Situation Board data model

SRS defines aggregated public output but does not fully specify whether it is:
- computed live from many collections
- maintained as denormalized public summary documents
- generated by backend functions.

Choose before production optimization.

## DEC-006 — Weather API

SRS requires an external weather API or manual admin entry but does not specify the provider.

Choose provider and API contract before implementing production integration.

## DEC-007 — OSM offline caching

SRS specifies pre-cache and offline-capable tiles, but exact production caching package/version/usage policy must be approved during implementation.

## DEC-008 — Admin hierarchy

SRS glossary includes province admin, commune admin and sector admin, while scope emphasizes commune-level operation.

Agent must follow the currently approved role matrix and not invent province/higher-level UI beyond defined requirements.
